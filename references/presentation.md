# 文档驱动的 Beamer 写作

先从原文记录一份工作大纲，每页包含页号、标题、来源章节、核心信息及图表位置。优先沿用原文的术语、层次和论证顺序。为口头讲述调整顺序时，保持证据与结论的对应关系。以下组织方式按报告内容选用。

| 文档类型 | 常用叙事 |
| --- | --- |
| 开题或研究计划 | 背景与缺口、研究问题、拟议方法、验证计划、进度与预期贡献 |
| 已有结果的研究报告 | 研究问题、数据与方法、主要结果、局限与结论 |
| 文献综述 | 问题范围、检索或纳入规则（原文提供时）、主题、证据差异与研究空白 |
| 阶段或项目报告 | 目标与现状、阶段成果及证据、未决问题与后续计划 |

页数是含封面的 PDF 总页数。目录、参考文献或结束页只有在需要时才占页，并计入总数。为减少页数，将相近章节合并并保留研究问题和关键证据。增加页数时拆分有实质内容的章节，补充分步解释或可核实的图表。每个 frame 默认一页，避免用 overlay、自动分节或 allowframebreaks 意外增加 PDF 页数。原文叙述未完成的实验或方案时，使用计划性的措辞。已报告的结果区分实测值、估计值和示意内容。

图表在有助于表达论点的页面出现。可将用户提供的原图作为证据，也可根据可核实的表格重绘。单位、样本口径、数值、分组标签和引用应与原文一致。没有可靠数据时使用概念图或方法流程图。用户未指定图数时，在文档内容支持的情况下规划约五张。

## 编译

先填写模板与图资源，再在工作目录保留编译中间文件：

    python3 /path/to/docx2latex/scripts/compile_beamer.py \
      /path/to/project/main.tex --pages 13 \
      --build-dir /path/to/work/qa --output /path/to/work/preview.pdf

按本次目标修改 --pages。脚本优先使用宿主机的 latexmk + XeLaTeX，缺失时探测本机已有的 Ayakaleaf 中文镜像。可用 --docker-image 指定已安装的兼容镜像。镜像中的编译进程断网，脚本不会下载镜像或修改 Docker 部署。页数验证需要 pdfinfo 或运行脚本的 Python 可导入 pypdf。编译环境需具备所用字体和宏包，例如中文模板的 CTeX、Fandol、Beamer、TikZ 和 booktabs。编译后用 pdftoppm 等逐页渲染，检查正文、公式和图表。
