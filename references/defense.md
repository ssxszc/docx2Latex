# 开题答辩制作参考

## 默认 13 页

| 页 | 内容 | 制作重点 |
|---|---|---|
| 01 | 封面 | 摘自报告的完整题名及必要答辩信息 |
| 02 | 研究背景及意义 | 场景如何产生问题，可用概念图 |
| 03 | 国内外研究现状 | 按方向归纳代表工作与缺口，保持原文献编号 |
| 04 | 核心问题或难例 | 用示意图展示输入、边界条件与预期行为 |
| 05 | 目标与关键问题 | 对应后续研究内容，并交代范围 |
| 06 | 整体方法与技术路线 | 对照原报告绘制输入、步骤、输出和已有设施 |
| 07 | 研究内容一 | 可用定义、公式及对应示意图 |
| 08 | 研究内容二 | 可配算法流程或具体机制图 |
| 09 | 下一研究内容或验证逻辑 | 依据报告实际研究内容组织 |
| 10 | 实验方案与可行性 | 拟用数据、基线、消融、控制变量和指标 |
| 11 | 特色与拟创新点 | 对齐原报告的技术贡献，避免把假设写成结论 |
| 12 | 进度及预期成果 | 日期与阶段来自报告，缺失时不用虚构 |
| 13 | 感谢聆听 | 一个结束 frame |

用户另有页数或顺序时按其要求调整。每个 frame 占一页，避免 overlay、allowframebreaks、自动目录和章节分页。引用可在对应页面用 [n] 链接至来源，无需另增一页。实验设计图可标注「示意」或「拟开展」，报告没有数据时不绘制看似实测的结果图。原报告若区分未知、缺乏证据和已证伪，应在图文中维持这种区分。

## 图稿简表

逐图写明用途、位置、来源段落、画面必须表达的节点及边、精确标签、状态和允许删减的细节。建议用白底、深色文字、低饱和度蓝／青绿／橙／灰、明确箭头和少量短标签。把长解释放在页面正文。找不到来自报告的可靠数字时采用机制或案例示意。对数学、流程和表格逐项核对，重点检查符号、箭头方向、时间先后及互斥关系。根据编译后呈现的尺寸判断可读性。

## 编译

先在交付目录中复制并填写模板。所有资源用相对路径。把临时编译文件放在交付目录外：

    python3 /path/to/thesis-proposal-beamer/scripts/compile_beamer.py \
      /path/to/project/开题报告.tex --pages 13 \
      --build-dir /path/to/work/qa --output /path/to/work/开题报告-验收.pdf

脚本优先使用宿主机的 latexmk + XeLaTeX，缺失时探测本机已有的 Ayakaleaf 中文镜像。可用 --docker-image 指定已有的兼容镜像。镜像中的编译进程断网，脚本不会下载镜像或修改 Docker 部署。页数验证需要 pdfinfo 或运行脚本的 Python 可导入 pypdf。运行前确保中英文字体、Beamer、CTeX、TikZ 和 booktabs 可用。页数改变时相应修改 --pages。验收 PDF 和页图留在工作目录。通过后用 pdftoppm 等逐页渲染视觉检查，检查正文、公式及科研图的位置和尺寸。
